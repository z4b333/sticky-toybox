# Third-party material

The project's own code is MIT (see LICENSE). Several things shipped alongside
it are not the project's own, and one of them raises a question I cannot answer
from here.

## The QR code library

`lib/QRCode/` is Richard Moore's QRCode, itself derived from Project Nayuki's
QR code generator. MIT, copyright 2017. Vendored so the project builds without
a network. The full notice is at the top of `lib/QRCode/src/qrcode.h`.

It carries one local change. `qrcode_initBytes` upstream does not check that
the payload fits the version it is given: it pads by subtracting the encoded
length from the capacity, which underflows when the data is too long, and then
writes through the error-correction region. The symbol draws, the call reports
success, and nothing decodes it. One line now rejects the version instead. See
the comment at the change, and the guard in `test/host/host_preview.cpp` that
holds it.

## Glyph data

The bitmap tables in `src/fonts_intl.cpp`, `test/host/fonts_cp.h` and the
downloadable `.tfp` packs are not fonts. They are 1-bit rasterisations of
specific glyphs at four fixed sizes, generated by `tools/make_fonts_intl.py`
and `tools/make_font_pack.py`. They are, however, derived from real fonts:

| Script | Source font | Licence |
|---|---|---|
| Latin, Vietnamese, European | DejaVu Sans | Bitstream Vera licence; DejaVu's own changes are public domain |
| Chinese, Japanese, Korean, kana | Noto Sans CJK | SIL Open Font License 1.1 |
| Thai | Loma (TLWG) | **GPL-2+ with the font exception — see below** |

Both DejaVu and Noto are permissive and untroubled by this use. Noto under the
OFL is exactly the case the OFL was written for.

## The unsettled question: Thai

Loma is GPL-2 or later, with the standard font exception. That exception says
that embedding the font, or unaltered portions of it, in a *document* does not
place the document under the GPL.

This project does not embed Loma in a document. It rasterises glyph outlines
into bitmaps and compiles those bitmaps into firmware. Whether that counts as
the exception's "embed this font or unaltered portions of this font", or as an
ordinary derivative work of a GPL-2 font, is not obvious, and I am not in a
position to decide it. If it is the latter, the firmware binaries distributed
here would arguably inherit GPL-2 terms, which is not what the MIT licence
above says.

Nobody has raised this and it may never matter. But it is a real ambiguity in
a repository that offers a one-click flashable binary, so it is written down
rather than left implicit.

**The clean fix, if it is ever wanted:** regenerate the Thai block from Noto
Sans Thai, which is OFL 1.1 like the rest of the Noto family, and the question
disappears. It is a two-line change in `tools/make_fonts_intl.py` — but not a
free one, because the Thai renderer's combining-mark placement was measured
against Loma's metrics specifically (`tools/thai_proof.py`), and swapping the
face means proving that work again.

This is not legal advice. If any of this matters commercially, ask someone
qualified.

## SSD1677 four-level grayscale waveform

The custom grayscale LUT in `src/epd.cpp` (`GREY_LUT`) -- 105 waveform bytes,
the Sticky voltage tail, and the multi-pass sequence around it (rails up
before the short LUT phases; border parked at VCOM; no revert waveform,
baseline resync instead) -- comes from the CrossPoint Reader project's
FreeInk SDK, whose Sticky profile carries the same table with per-module
tuning notes, cross-checked against the papyrix-reader project's SSD1677
driver documentation. Both are MIT licensed.

## miniz (lib/miniz/third_party/)

miniz 3.1.2 by Rich Geldreich, vendored for its streaming inflate (tinfl),
which the EPUB reader uses to read zip entries. Compiled decompress-only via
`lib/miniz/src/toybox_miniz.h`, whose tinfl_* symbol renames -- guarding
against the ESP32 mask ROM's incompatible built-in copy -- follow the
vendoring notes in the CrossPoint Reader project. miniz is public domain
(unlicense); see the statement at the end of miniz.c.

- https://github.com/richgel999/miniz (public domain)

## CrossPoint-derived parts

The EPUB reader's position record (spine index plus a visible-codepoint
offset) and its counting rules were learned from CrossPoint Reader and
reimplemented: the hashes, the record layout, the invisible-tag list and the
offset counting in `toybox-core/src/epubcore.cpp` are Toybox's own code. Since
v2 the position lives in the book's own folder; CrossPoint's directory is
read only to move a pre-v2 position across.

One piece is **not** reimplemented. `toybox-core/src/tools/epub/epub_entities.h`
is the HTML named-entity table from CrossPoint's `htmlEntities.cpp` (MIT,
Copyright (c) 2025 Dave Allie), itself derived from atomic14's
diy-esp32-epub-reader (MIT), copied verbatim and compiled into the firmware.
Kept verbatim: saved positions and bookmarks count codepoints of the
rendered text, so a table that expanded one entity differently would move
every saved place after it -- silently, on one book, at one paragraph.

- https://github.com/crosspoint-reader/crosspoint-reader (MIT, Copyright (c) 2025 Dave Allie)
- https://github.com/atomic14/diy-esp32-epub-reader (MIT)

## KOReader / Readest progress sync

Reading-position sync speaks the KOReader sync protocol, by default to
Readest's server, which offers it for e-ink readers. The protocol (endpoints,
headers, the partial-MD5 document id, the xpointer form, the device sign-in)
was learned from the KOReader and Readest sources (both AGPL-3.0) and from
their public behaviour; `toybox-core/src/tools/kosync.h`, `md5_tiny.h` and the
xpointer code in `epubcore.cpp` are Toybox's own code. No KOReader or Readest
code is compiled into Toybox. Talking to a server over its protocol is
interoperability, not derivation.

- https://github.com/koreader/koreader (AGPL-3.0)
- https://github.com/readest/readest (AGPL-3.0)

## TJpgDec (lib/tjpgd/)

TJpgDec R0.03 by ChaN, vendored for the EPUB cover thumbnails (baseline JPEG
decode, configured for grayscale output in lib/tjpgd/src/tjpgdcnf.h). ChaN's
license permits use, modification and redistribution for any purpose with the
copyright notice retained; see the header of tjpgd.c. The ESP32-S3 mask ROM
carries an older build of this module behind weak PROVIDE symbols; the
vendored strong definitions override it. Progressive JPEG covers are handled
by Toybox's own DC-scan extractor (tools/epub/epub_jpegdc.h), and PNG covers
by Toybox's own decoder over the vendored miniz inflate
(tools/epub/epub_png.h).

- http://elm-chan.org/fsw/tjpgd/ (via espressif/idf-extra-components)

## Reading typefaces (tools/fonts/, baked into src/fonts_read.h)

The EPUB reader's optional typeface, under the SIL Open Font License 1.1,
rasterised to 1-bit tables by tools/make_fonts_read.py from the files vendored
in tools/fonts/ — roman, bold and italic:

- **Literata** — copyright TypeTogether, commissioned by Google for Play
  Books. https://github.com/googlefonts/literata

The OFL permits embedding and redistribution; the font files themselves are
carried unmodified in tools/fonts/ so the tables can be regenerated.
