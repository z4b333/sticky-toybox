A screen that remembers.

Toybox is firmware for the Seeed reTerminal Sticky — an e-paper device that reads your books, holds notes you write from your phone, and keeps a drawer of small games.

No backlight. No notifications. Nothing to charge this week.

Filling the card

Comics and books, cut to fit.

The reader opens EPUBs off the card as they are. Comics are the harder case — a webtoon is one strip a mile long, and a manga page is wider than the panel — so there is a desktop tool for that.

Toybox Slicer takes .cbz chapters, loose images or an EPUB and writes .tbk pages at the panel's own 480×800. For a webtoon it stitches the slices back into one strip and re-cuts it, snapping every cut to a blank gutter so a page never lands through a face or a speech bubble. It makes sleep art and wallpapers too, in batches, which is the difference between it and the one-picture converter here.

Python, with a window if you double-click it and a command line if you would rather script it.

Install

Flash it from this page.

  1. Plug the Sticky in with a USB-C cable that carries data. A charging cable will not do, and it is the commonest reason nothing appears. Nothing showing up?
  2. Tick any language packs you want. The common characters are already in the firmware; these add the rest.
  3. Press UPDATE. Reading which build is here…

When the browser asks about erasing the device, leave the box unchecked. Unchecked, an install writes the firmware and nothing else — notes, settings, saved pages, decks and font packs all survive. Ticked, they do not.

UPDATE is the one to use for every build after your first. FIRST INSTALL adds the bootloader and partition table — needed once on a new device, or to rescue one that will not boot.

After installing

Two minutes, once.

The service screen is worth a visit before anything else. It reports what the board answered on each bus, and can correct the screen or touch orientation if your unit disagrees with mine.

  1. The first boot takes a few extra seconds while it sets up storage.
  2. Hold either side button while it powers on the first time. That reaches the service screen; there is a tickable checklist for a phone held next to the device.
  3. Tap any tile on the hub to play.
  4. Open Notes → Write, scan the QR code with your phone, and type or dictate a note.
  5. Pin a note and it stays on the screen even with the power off. That is the whole idea.

The idea

Why this exists.

The Sticky is a lovely bit of hardware with an e-paper panel that keeps its last picture when the power is gone. Most things built on that treat the screen as a dashboard — something to glance at. I wanted the opposite: a screen you put something on and then forget about, because it will still be there in a month.

So the notes app is the point, and the reader is what I use it for most, and the games are there because a screen that redraws in a fifth of a second turns out to suit a crossword far better than it suits a video. Everything here is written for this one device and its 480 by 800 pixels, which is a constraint I have enjoyed more than I expected to.

Built by KS. The firmware, the converter and this page are all open source; if it does something you did not ask for, the code is there to change.

If something goes wrong

Help.

No serial port showing up?
  • Use a data-capable USB-C cable, not a charging cable.
  • On Windows, install the CH343 driver. The Sticky uses a CH34x serial chip.
  • Still nothing? Hold the power button while plugging in, then try Install again.
Prefer the command line?

Update, keeping everything:

esptool --chip esp32s3 write_flash 0x10000 toybox-app.bin

First install (also writes bootloader and partition table; note this one resets the device's settings):

esptool --chip esp32s3 write_flash 0x0 toybox-full.bin

Download toybox-app.bin or toybox-full.bin.

Will an update wipe my notes?

No. Every part is written at its own offset and the gaps between them are never touched: settings and saved reading pages live in NVS, notes and decks and pictures in the filesystem, and neither is in the firmware's way. The one thing that does wipe them is ticking the erase device box in the browser's dialog, which is why it is worth reading that dialog rather than clicking through it.
