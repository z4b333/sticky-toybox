# Toybox

เกมและเครื่องมือเล็ก ๆ สำหรับ **Seeed reTerminal Sticky** (ESP32-S3 + จอ e-paper 3.97" 800×480 + ทัชสกรีน) — อะไรก็ตามที่หยิบมาเล่นหรือใช้ตอนว่าง ควบคุมด้วยการแตะจออย่างเดียว

ทุกหน้าจอวางเลย์เอาต์แบบ **แนวตั้ง 480×800** (ถือเครื่องตามยาว) การหมุนอยู่ในไดรเวอร์จอที่ `drawPixel()` เพียงจุดเดียว ทั้งภาพและตัวอักษรจึงหมุนตามหมด และการแตะถูกแปลงกลับใน `touch.cpp` ให้ตรงกัน ถ้าอยากกลับไปเป็นแนวนอน ให้คอมเมนต์ `#define TOYBOX_PORTRAIT 1` ใน `src/board_pins.h` (แต่เลย์เอาต์ทุกหน้าถูกออกแบบมาสำหรับแนวตั้งแล้ว)

## ระเบียบขนาดตัวอักษร และตัวตรวจข้อความล้นจอ

จอนี้ 235 DPI ขนาดตัวอักษรจึงแปลงเป็นขนาดจริงได้ตรง ๆ:

| | พิกเซล | ขนาดจริง | ใช้กับ |
|---|---|---|---|
| `TS_HUGE` | 32 | 3.4 มม. | คะแนน แต้มลูกเต๋า ตัวเลขพาดหัว |
| `TS_LARGE` | 24 | 2.6 มม. | ปุ่มหลัก หัวข้อหน้าจอ |
| `TS_MED` | 16 | 1.7 มม. | **เนื้อความ คำอธิบาย ปุ่มรอง** |
| `TS_SMALL` | 8 | 0.9 มม. | ป้ายคำเดียว/เชิงอรรถเท่านั้น |

`TS_SMALL` เล็กเกินกว่าจะอ่านเป็นประโยคได้สบาย เดิมถูกใช้เป็นเนื้อความไป **69 จุด**
ซึ่งเป็นสาเหตุหลักที่หน้าจอดู "ไม่เป็นมิตร" ตอนนี้เหลือ 5 จุดที่เป็นป้ายสั้น ๆ จริง ๆ

การขยายตัวอักษรทำให้ข้อความยาวเกินขอบจอได้ง่าย และบนเครื่องจริงมันจะถูก**ตัดทิ้งเงียบ ๆ**
(เพราะ `drawPixel` clip อยู่แล้ว) จึงใส่ตัวตรวจไว้ใน `gfx::drawText` เฉพาะ host build:
ข้อความไหนวาดออกนอกจอจะถูกบันทึกพร้อมชื่อหน้าจอ แล้วรายงานท้ายการรันพรีวิว

ตัวตรวจนี้จับบั๊กที่หลุดไปแล้วได้ทันที 1 จุด (`"tap the card to reveal"` ในหน้าแฟลชการ์ด
กว้าง 528 px บนจอ 480 px) และจับอีก 7 จุดที่ *เพิ่งเกิด* จากการขยายตัวอักษรในรอบนี้เอง

## รายละเอียดภาพสองจุด

**2048 — ไทล์ใหม่กับไทล์ที่เพิ่งรวม** หลังปัดหนึ่งครั้งมีของใหม่บนกระดาน 2 อย่างที่ตาต้องหาเจอ:
ไทล์ที่ระบบสุ่มเพิ่มเข้ามา และไทล์ที่เกิดจากการรวม ตอนนี้แยกกันด้วยวิธีคนละแบบ —
ไทล์ใหม่วาด**ขอบเส้นประ** (ค้างไว้จนกว่าจะปัดครั้งถัดไป) ส่วนไทล์ที่เพิ่งรวม**กะพริบ**หนึ่งครั้ง
โดยวาดสลับสีกับไทล์อื่นราว 450 มิลลิวินาที แล้ว `tick()` ค่อยวาดกลับเป็นปกติ

ลำดับนี้ตั้งใจให้เป็น "เน้นก่อน แล้วค่อยนิ่ง" ไม่ใช่ "นิ่งก่อนแล้วค่อยเน้น" เพราะถ้าทำกลับกัน
จะมีการรีเฟรช e-ink ไปคั่นระหว่างการปัดกับผลลัพธ์ ทำให้รู้สึกหน่วง

การกะพริบใช้วิธี**วาดสลับสี**กับไทล์ปกติ ไม่ใช่เติมสัญลักษณ์เพิ่ม จึงอ่านออกไม่ว่าไทล์นั้นค่าเท่าไร
(ไทล์ตั้งแต่ 128 ขึ้นไปปกติเป็นสีทึบอยู่แล้ว ตอนกะพริบจะกลายเป็นขอบโปร่งแทน) และไม่กินพื้นที่เพิ่ม

**ตัวเลือกชนิดลูกเต๋าเป็นรูปทรงจริง** แถวเลือก D4/D6/D8/D10/D12/D20 วาดเป็นภาพลายเส้นของทรงตันจริง ๆ
(tetrahedron, cube, octahedron, trapezohedron, dodecahedron, icosahedron) แทนที่จะเป็นแค่ตัวอักษร
รูปทรงถูกจำได้ก่อนที่ตัวหนังสือจะถูกอ่าน และการย้ายจาก 2 แถวเหลือแถวเดียวยังลดความสูงลงได้อีก 18 px
ปุ่มที่เลือกอยู่กลับสีทั้งกรอบและลายเส้น (`dshape::draw()` จึงรับพารามิเตอร์ `black` ไว้ด้วย)

ทุกทรงสร้างจากวงแหวนจุดยอดของ n-gon บวกเส้นภายในไม่กี่เส้น — คือเงาของทรงตันเวลามองเข้าที่มุม
ซึ่งเป็นมุมที่ลูกเต๋าถูกวาดบนกล่องเสมอ ตอนแรก D20 ใช้มุมหมุนเดียวกับกรอบนอก ทำให้ซี่หนึ่งเป็นแนวรัศมี
และลายออกมาเป็นกังหัน แก้โดยหมุนหน้าสามเหลี่ยมด้านในไป 60 องศา มุมแต่ละมุมจึงอยู่กึ่งกลางระหว่าง
มุมของกรอบนอกสองมุมและโยงออกไปทั้งคู่

**ลูกเต๋าเป็นทรงลูกเต๋าจริง** หน้าลูกเต๋าเดิมเป็นสี่เหลี่ยมมุมฉาก ตอนนี้มุมโค้งด้วยรัศมี 1/6 ของด้าน
ซึ่งใกล้เคียงลูกเต๋าพลาสติกจริง และพอที่จะอ่านออกว่าเป็น "ลูกเต๋า" ไม่ใช่ "กล่องที่มีจุด"
ไอคอนในหน้าแรกใช้ทรงเดียวกันแล้ว

canvas มีแค่สี่เหลี่ยมกับวงกลม ไม่มีคำสั่งวาดส่วนโค้ง `tdraw::roundRect()` จึงประกอบจากแถบตรง 3 แถบ
บวกวงกลมเต็มที่มุมทั้งสี่ ถ้าต้องการแบบมีขอบก็วาดทึบก่อนแล้วทาส่วนในกลับด้วยสีขาว
วิธีนี้ทำให้ความหนาของขอบเท่ากันตลอดแนวรวมถึงตรงมุมโค้ง

## หน้าวิธีเล่น

เกมทุกเกมจะขึ้นการ์ด **HOW TO PLAY** ให้อัตโนมัติในครั้งแรกที่เปิด มีสองปุ่ม:

- **GOT IT** — ปิดเฉพาะครั้งนี้ เปิดเกมใหม่ก็ยังขึ้นอีก
- **DON'T SHOW AGAIN** — เขียนแฟลกลง NVS แล้วจะไม่ขึ้นเองอีกเลย

ปุ่ม **?** มุมขวาบนเรียกการ์ดกลับมาดูได้ทุกเมื่อ ซึ่งเป็นเหตุผลที่ปุ่ม "ไม่ต้องแสดงอีก" ปลอดภัยพอจะกด —
ถ้าไม่มีทางกลับ ปุ่มนั้นจะกลายเป็นประตูที่ล็อกตัวเอง และไม่มีใครกล้ากด
(ปุ่ม ? จะวาดเฉพาะหน้าจอที่มีการ์ดจริง ๆ เท่านั้น กดแล้วต้องมีอะไรเกิดขึ้นเสมอ)

การ์ดวางทับหน้าจอที่เล่นค้างอยู่ ไม่ได้ล้างเกม กด GOT IT แล้วกลับมาที่เดิม
เทสต์พรีวิวตรวจครบวง: การ์ดกันการแตะไม่ให้ทะลุไปโดนเกมข้างล่าง, GOT IT ปิดแค่ครั้งเดียวจริง,
DON'T SHOW AGAIN บันทึกลง NVS จริง และปุ่ม ? เรียกกลับมาได้จริง

## การเขียนโน้ตจากมือถือ

1. เข้าแอพ NOTES แล้วกด **WRITE** (หรือกด EDIT ตอนเปิดโน้ตอยู่)
2. ส่อง QR ด้วยกล้องมือถือ → หน้าแก้ไขเด้งขึ้นเอง
3. พิมพ์ หรือ **กดปุ่มไมค์บนคีย์บอร์ดมือถือแล้วพูด** (iOS/Android ถอดเสียงบนเครื่องได้ ไม่ต้องใช้เน็ต)
4. ใช้แถบปุ่มจัดรูปแบบ (Title / Heading / Bullet / Number / Checkbox / Quote / Bold / Divider) — กดแล้วแทนที่รูปแบบเดิมของบรรทัดนั้น ไม่ซ้อนกัน
5. ดูพรีวิวว่าขึ้นจอจริงหน้าตาแบบไหน แล้วกดส่ง
6. พอโน้ตมาถึง เครื่องจะถามว่า **SHOW ON SCREEN** (ปักหมุด) หรือ **JUST SAVE** (เก็บไว้ในรายการเฉย ๆ)

เลือกโน้ตเดิมจาก dropdown เพื่อแก้ต่อได้ · โน้ตเก็บเป็นไฟล์ `.md` ใน `/notes/`

### โน้ตค้างจอ (lock screen)

จอ e-paper เก็บภาพไว้ได้โดยไม่ใช้ไฟ ดังนั้นโน้ตที่ปักหมุดไว้จะ**ค้างอยู่บนจอหลังปิดเครื่อง** —
กลายเป็นโน้ตแปะตู้เย็นจริง ๆ ที่อ่านได้ตลอดโดยไม่กินแบตเลย

- ปักหมุดได้ 2 ทาง: ตอบ **SHOW ON SCREEN** ตอนโน้ตมาถึง หรือกดปุ่ม **PIN** ตอนเปิดอ่านโน้ตนั้น
- ในรายการโน้ต ตัวที่ปักหมุดจะมีจุดทึบข้างหน้าและกรอบหนากว่า
- กด **UNPIN** เพื่อเอาออก แล้วหน้าปิดเครื่องจะกลับไปเป็นการ์ด GOODBYE ตามเดิม
- ถ้าลบโน้ตที่ปักหมุดไว้ ระบบถือว่าไม่มีหมุด ไม่ค้างภาพเก่า

## การใส่รายการ PICKER จากมือถือ

พิมพ์ชื่อ 10 ชื่อบนคีย์บอร์ด 8x8 บนจอ e-ink เป็นงานที่ทรมานที่สุดในเฟิร์มแวร์ ปุ่ม **FROM PHONE**
ในหน้า PICKER จึงเปิดหน้าเว็บบนมือถือแบบเดียวกับโน้ต/แฟลชการ์ด (สแกน QR → หน้าเว็บเด้งเอง)

หน้าเว็บเป็นกล่องข้อความล้วน **หนึ่งบรรทัด = หนึ่งรายการ** พร้อมปุ่ม Tidy / Sort A-Z / Clear
และตัวนับที่เตือนทันทีเมื่อเกิน 10 รายการหรือชื่อยาวเกิน 20 ตัวอักษร

- หน้าเว็บเปิดมาพร้อมรายการที่อยู่บนเครื่องจริง ๆ (อ่านผ่าน `/items`) แก้แล้วกด Save ทับได้เลย
- เซิร์ฟเวอร์ไม่ได้ถือรายการเอง แต่รับ reader/writer จากตัวเครื่องมือ NVS จึงเป็นแหล่งข้อมูลเดียว
  การแก้จากคีย์บอร์ดบนจอกับจากมือถือไม่มีทางไม่ตรงกัน
- ตัวแปลงข้อความอยู่ที่ `plist::fromText()` ที่เดียว ใช้ร่วมกันทั้งสองทาง: ตัดบรรทัดว่าง ตัดช่องว่างหัวท้าย
  ตัดชื่อที่ยาวเกิน และ**แปลงอักษรละตินมีเครื่องหมายเป็นตัวพื้นฐาน** (José → Jose) แทนที่จะทิ้งหรือแสดงเป็นขยะ
  (ภาษาไทยยังแสดงไม่ได้ จะกลายเป็น `?` เพราะฟอนต์เป็น ASCII)

## การส่งแฟลชการ์ดจากมือถือ

1. เข้าแอพ STUDY แล้วกด **IMPORT**
2. เครื่องปล่อย WiFi ของตัวเอง (ชื่อ `TOYBOX-xxxx` รหัสสุ่มใหม่ทุกครั้ง) แล้วโชว์ QR
3. เปิดกล้องมือถือส่อง QR → มือถือเข้า WiFi ให้อัตโนมัติ (รองรับ iOS 11+/Android 10+)
4. หน้าเว็บจะเด้งขึ้นเอง (captive portal) — ถ้าไม่เด้ง กดปุ่ม **PAGE DIDN'T OPEN?** บนเครื่องเพื่อสลับเป็น QR ลิงก์ (หรือพิมพ์ `192.168.4.1` เอง)
5. วางข้อความหรือเลือกไฟล์ CSV/TSV แล้วกดส่ง เครื่องปิด WiFi เองเมื่อกด DONE

หน้าเว็บมีคำอธิบายรูปแบบครบพร้อมตัวอย่างและปุ่ม "Use this example" กดแล้วเติมให้เลย
และมีลิงก์ไปคู่มือ export ของ Anki กับ Quizlet (ลิงก์ต้องใช้เน็ตมือถือ เพราะ WiFi ของเครื่องไม่มีอินเทอร์เน็ต — ตัวอย่างในหน้าใช้ได้แบบออฟไลน์)

รูปแบบข้อมูล: บรรทัดละใบ คั่นด้วย **tab, `|`, จุลภาค (รองรับเครื่องหมายคำพูด) หรือ ` - `**
รองรับไฟล์ export จาก Anki และ Quizlet ตรง ๆ · การนำเข้าสำรับชื่อเดิมซ้ำจะ**เก็บความคืบหน้า**ของใบที่ข้อความหน้าไม่เปลี่ยนไว้ให้

- ไทล์ไม่มีกรอบ พื้นที่แตะจึงกินทั้งแถบ รวมช่องว่างระหว่างคอลัมน์ แถบหัวกลุ่ม ช่องว่างท้ายกลุ่ม

> ลองมาแล้ว 3 แบบ: ตารางล้วนไม่มีหัวกลุ่ม (รับได้ 18 แอพ แต่ไม่บอกว่าแอพไหนใช้ทำอะไร),

> และแบบที่ใช้อยู่นี้ซึ่งได้หัวกลุ่มมาโดยเสียความจุแค่ 3 ช่องและไม่เสียความแม่นในการแตะเลย

## Sudoku: การสุ่มโจทย์

โจทย์ทุกใบสร้างสดบนเครื่อง ไม่ได้เก็บตารางสำเร็จรูปไว้ ขั้นตอนคือเติมตารางให้เต็มด้วย backtracking
แบบสุ่มลำดับตัวเลข แล้วค่อย ๆ ลบตัวเลขออกทีละช่อง โดยหลังลบแต่ละครั้งจะ**นับจำนวนคำตอบ**
ถ้าเหลือมากกว่า 1 คำตอบก็ใส่กลับคืน — โจทย์ที่มีสองคำตอบไม่ใช่ซูโดกุ และผู้เล่นจะไม่มีทางรู้
จนกว่าจะเสียเวลาไปแล้วเป็นชั่วโมง

ระดับความยากกำหนดด้วยจำนวนตัวเลขที่เหลือ: EASY 40, MEDIUM 32, HARD 26 (ทดสอบแล้วว่าเข้าเป้าเป๊ะทุกครั้ง)

ตัวนับคำตอบเลือกช่องที่มีตัวเลือกน้อยที่สุดก่อนเสมอ และทำงานจากบิตมาสก์ของแถว/คอลัมน์/บ็อกซ์
ที่สร้างใหม่รอบละครั้ง ไม่ใช่ไล่เช็คทีละตัวเลข ตอนแรกที่ใช้วิธีเลือกช่องว่างช่องแรก HARD ใช้เวลา
สร้างนานสุดถึง 134 ms บนเครื่องพัฒนา (บนบอร์ดจริงคือหลายวินาที) หลังแก้เหลือ **1.6 ms เฉลี่ย
แย่สุด 7.1 ms** ซึ่งซ่อนอยู่ใต้เวลารีเฟรชจอ e-ink ได้สบาย

- ตัวเลขโจทย์วาดตัวใหญ่+หนา ส่วนตัวเลขที่ผู้เล่นใส่วาดเล็กกว่าหนึ่งขนาด (จอ 1 บิตไม่มีสีเทาให้ใช้
  และแค่ตัวหนาอย่างเดียวดูไม่ออกที่ขนาดนี้ — ขนาดคือสิ่งที่แยกออกด้วยการชำเลืองมอง)
- ช่องตาราง 48 px = 5.1 มม. ซึ่งเล็กกว่าปลายนิ้ว แต่**การเลือกช่องไม่ commit อะไรเลย**
  แตะพลาดก็แค่แตะใหม่ ส่วนการใส่เลขจริง ๆ ไปผ่านปุ่มตัวเลขขนาด 9 มม. ทั้งหมด
- ปุ่มระดับความยากแค่เลือกไว้สำหรับใบถัดไป ไม่ล้างโจทย์ที่เล่นค้างอยู่ — มีแต่ปุ่ม NEW เท่านั้นที่ล้าง
- ไม่มีการเช็คผิดรายช่องตามที่ตั้งใจ แต่เมื่อกรอกครบทั้งกระดานจะบอกว่าถูกทั้งหมด หรือผิดกี่ช่อง
  (บอกจำนวน ไม่บอกตำแหน่ง) มิฉะนั้นเกมจะไม่มีจุดจบ

## เล่น 2 เครื่อง (ESP-NOW)

SHIPS เล่นข้ามเครื่องได้โดยไม่ต้องมีเราเตอร์หรือ AP: ESP32-S3 คุยกันตรง ๆ ด้วย **ESP-NOW**
เครื่องหนึ่งกด HOST A GAME แล้วโชว์รหัส 4 หลัก อีกเครื่องกด JOIN A GAME แล้วแตะรหัสนั้น
(รหัสมาจาก MAC ของเครื่อง มีไว้ยืนยันว่าจับคู่ถูกคน ไม่ใช่คู่ที่นั่งโต๊ะข้าง ๆ)

ข้อความในโปรโตคอลเล็กมาก — การยิงหนึ่งครั้งคือ 2 ไบต์ — และ**ทุกข้อความ idempotent**
นัดยิงมีหมายเลขลำดับ ฝ่ายรับที่เจอลำดับซ้ำจะตอบจากผลที่บันทึกไว้ ไม่ยิงซ้ำ การส่งใหม่จึงไม่มีทาง
เจาะเรือลำเดิมสองรู

โครงสร้างแยกเป็น 3 ชั้นเพื่อให้ทดสอบได้จริง:

- `link.h` — ตัวส่งข้อความ ESP-NOW ล้วน ๆ ไม่รู้เรื่องเกม (บนโฮสต์ อินสแตนซ์คุยกันในโปรเซสเดียว)
- `sea_net.h` — โปรโตคอลการดวล (จับคู่ / พร้อม / ยิง / ผล / ขอเล่นใหม่) ไม่มีจอเข้ามาเกี่ยว
- `tool_sea.h` — หน้าจอ

เทสต์บนโฮสต์ตั้ง `Duel` สองตัวเล่นกันจริง รวมถึงเกมที่**สั่งให้วิทยุทิ้งแพ็กเก็ต**ระหว่างทาง
(ตอนกระจายสัญญาณ, ตอน JOIN/ACCEPT, ตอนจับมือ READY และตอนส่งผลการยิง) ซึ่งเป็นความล้มเหลว
ที่จำลองบนเครื่องจริงสองเครื่องบนโต๊ะไม่ได้ เทสต์ชุดนี้จับบั๊ก deadlock ได้ 2 ตัวระหว่างพัฒนา

## การใช้หน่วยความจำ (สำคัญกับการพอร์ตเข้า CrossPoint)

Toybox ที่ยังไม่ได้เปิดใช้ควรกินทรัพยากรของเครื่องอ่านหนังสือให้น้อยที่สุด โค้ดที่ไม่ถูกเรียกไม่ทำให้ช้า
(ESP32 รันจากแฟลชผ่านแคช) ตัวที่กินจริงคือ RAM แบบ static ที่จองตั้งแต่บูตไม่ว่าจะเปิดใช้หรือไม่
จึงย้ายก้อนใหญ่ทั้งหมดไปไว้บนฮีปแบบจองตอนใช้ คืนตอนออก:

| | ก่อน | หลัง |
|---|---|---|
| static RAM ของ `src/*.o` | 40,864 B | **831 B** |
| ทั้งเฟิร์มแวร์ | 87,380 B (26.7%) | **47,324 B (14.4%)** |

- `fcard::ImportScratch` (~34 KB) จองเฉพาะตอน import แล้ว `free` ทันที
- `ToolShell` สร้างเครื่องมือที่เปิดอยู่ตัวเดียวบนฮีป (`select`/`release`) เหลือแค่พอยน์เตอร์
- ตารางบล็อก Markdown ตอนวาดโน้ตค้างจอจองเฉพาะตอนกำลังจะปิดเครื่อง
- LittleFS mount แบบ lazy (ครั้งแรกที่เปิดแฟลชการ์ด/โน้ตเท่านั้น) ไม่แตะตอนบูต
- WiFi เปิดเฉพาะตอนอยู่หน้าจับคู่ และปิดด้วย `softAPdisconnect` + `WIFI_OFF` เมื่อออก

เทสต์พรีวิวมีลูป เปิด/ปิดเครื่องมือทั้ง 7 ตัว 3 รอบ + import ซ้ำ สำหรับรันใต้
`-fsanitize=address,undefined` เพื่อจับ use-after-free / double free ในเส้นทางนี้

## Hardware notes (สรุปจากการ reverse-engineer ของโปรเจกต์ CrossPoint/FreeInk)

- **Power latch:** GPIO45 + GPIO46 ต้องดัน HIGH ทันทีตอนบูต ไม่งั้นเครื่องดับเมื่อถอด USB
- **จอ:** SSD1677, SPI (SCK13 MOSI14 CS15 DC16 RST17 BUSY18), rail enable GPIO47
  - full refresh: CTRL2=0xF7 (~1.7s) / partial: CTRL2=0xFF (เร็ว, diff กับเฟรมก่อนหน้า)
  - แกน Y ของ RAM กลับด้าน (gate reversed) — จัดการใน `epd.cpp` แล้ว
- **ทัช:** GT911 (I2C SDA3 SCL2, INT21 RST41, rail GPIO42) — พิกัดเริ่ม byte 0 (ไม่มี track-id), ต้อง swap XY + flip ทั้งสองแกน
- **ปุ่ม:** UP=GPIO5, DOWN=GPIO6, OK/PWR=GPIO4 (active low) • **Buzzer:** GPIO48
